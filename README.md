## Image tags

Releases follow the contract in [`renovate.example/image-versioning.md`](renovate.example/image-versioning.md):

```text
anthonysautomations/github-runner:<YYYY>.<MM>.<DD>.<N>-arm64
```

`YYYY.MM.DD` is the UTC build date, `N` a 1-based sequence within that date and
architecture. These tags are **immutable** — the build allocates the next free
sequence with `scripts/allocate-version.sh` and aborts rather than overwrite an
existing release. `latest-arm64` also moves with each build, but is convenience
only; anything deployed should pin a versioned tag. Until the first release
under this contract is published, Compose uses `latest-arm64`; immediately then,
replace it with the new immutable `<version>-arm64` tag and add a Renovate Docker
annotation to keep that pin current.

Provenance lives in OCI labels (`version`, `revision`, `source`, `created`, plus
the pinned base image) and in an SBOM attestation generated by BuildKit from the
image actually pushed:

```sh
docker buildx imagetools inspect --format '{{ json .SBOM }}' anthonysautomations/github-runner:<tag>-arm64
```

The commit is also baked in as `GIT_COMMIT` for tracing a running container
(`docker exec <container> printenv GIT_COMMIT`); treat it as best-effort and use
the image digest for a binding record.

The base image is pinned by digest. Renovate updates that digest within the
Ubuntu 24.04 line; `scripts/test-allocate-version.sh` smoke-tests allocator
behaviour against both the real public repository and a generated missing name.

> **Migration:** the unsuffixed `latest` tag is no longer published — a
> single-architecture pipeline must not claim an architecture-agnostic tag.
> Existing consumers of `latest` have to be repointed; `github-runner/docker-compose.yml`
> already is.

## Dependency updates

`renovate.json` and `.github/workflows/renovate.yml` run Renovate against this
repository every Friday (and on demand via **Run workflow**) to bump the pins in
`github-runner/Dockerfile`: the Ubuntu base image, `GITHUB_RUNNER_VERSION` and
`ADO_AGENT_VERSION`.

- Updates are grouped into a single `renovate/*` branch per run and automerged
  once `.github/workflows/validate-build.yml` — a build-only run of the runner
  image on the ARM64 runner — reports a green check. That check is dispatched by
  the Renovate workflow itself, because the built-in `GITHUB_TOKEN` cannot start
  workflow runs from its own pushes.
- GitHub Actions version bumps are listed on the dependency dashboard issue
  instead of being raised as PRs; `GITHUB_TOKEN` may not write under
  `.github/workflows`, so they are applied by hand.
- `sonarqube/` and `renovate.example/` are excluded from Renovate.
